# Islamic Reconstruction

TEXTUAL MEANING
→ CLASSICAL INTERPRETATION
→ INTERNAL DISAGREEMENT
→ CONTEMPORARY RECONSTRUCTION
→ AI APPLICATION

## Stage requirements

**TEXTUAL MEANING**: cite the specific ayat/hadith for ukhuwah under investigation. Note which are muhkam and which require interpretation.

**CLASSICAL INTERPRETATION**: cite specific exegetes/works, not "classical scholars say." Note where tafsir bil-ma'tsur and tafsir bir-ra'yi readings diverge.

**INTERNAL DISAGREEMENT**: map disagreement across schools/scholars as an actual claim graph (`core/claim-graph.md`), not one averaged position.

**Before CONTEMPORARY RECONSTRUCTION**, do both:
1. Identify the 'illah (operative cause) of ukhuwah in the sources above. Analogical extension (qiyas) to a new case — AI — is only defensible if the 'illah is identified and the new case is checked for whether it actually shares it. A word-level match ("both called ukhuwah") without a shared 'illah is semantic stretch, not reconstruction.
2. Check the proposed concept against the existing typology of ukhuwah (e.g. ukhuwah islamiyyah/diniyyah, ukhuwah wataniyyah, ukhuwah insaniyyah/basyariyyah) as the nearest neighboring concepts the Emergent concept rule already requires checking against. State explicitly what Ukhuwah Dzakaiyah shares with, and departs from, each.

**AI APPLICATION**: state which maqāṣid al-syarī'ah is served or put at risk, and how — this is the ethical-defensibility half of PROJECT-CONTEXT.md's success condition, not a separate afterthought.

## Keep separate
- explicit source content,
- interpreter argument,
- contemporary reconstruction,
- proposed AI application.

Never manufacture consensus. If no 'illah can be identified, or the typology check finds no genuine gap, that is a valid result — route it through the Decision vocabulary (likely SYNONYM or NORMATIVE_CATEGORY) rather than forcing AI APPLICATION anyway.
